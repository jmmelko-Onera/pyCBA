CORRECTIFS MATLAB - scripts de conversion (hors MAIN)
=====================================================
Les trois scripts sont portes dans pycba/io/converters.py (versions corrigees).
Points verifies sur les fichiers d'exemple sont marques [verifie]; les autres [lecture du code].

--- MAIN_PhotonPRW_to_ASCII.m ---------------------------------------------------------------

P1. [lecture du code - bloqueur] Lignes 70-71 : "endif strcmp(mode,AutoMode)" n'est pas du MATLAB
    (c'est un "end" + un "if" fusionnes). Le script plante en mode Automatique. Remplacer par :
        end
        if strcmp(mode,AutoMode)
    (le test "if strcmp(mode,'')" qui suit est alors dans le bon bloc.)

P2. [verifie] Detramage : la boucle "while (i < dimY-1)" oublie la derniere paire de lignes
    (pour dimY=1024 la ligne 1023 n'est jamais remplacee). Remplacer par :
        while (i < dimY)
    (il faut juste que la ligne i+1 existe).

P3. [lecture du code] Ligne 138 : warning(['Fichier ',FileName,...]) -> FileName est un cell array,
    erreur "Cell contents..." ; utiliser FileName{kk}.

P4. [verifie] La taille de l'image est dans l'en-tete du fichier : les 4 premiers octets sont
    2 x uint16 (largeur, hauteur) -> 00 05 00 04 = 1280 x 1024. Le "fseek(f,4,-1)" saute donc
    cet en-tete, mais la devinette de taille (divisor + questdlg) est inutile et peut se tromper.
    Remplacement possible :
        hdr = fread(f,2,'uint16');   dimX = hdr(1);  dimY = hdr(2);
        r1  = fread(f,'uint16');

P5. [choix a confirmer] r2=round(r2*dimZ/max(max(r2))) rescale CHAQUE image sur 0..255 : le gain
    change d'une image a l'autre (energie / puissance non comparables) et les 872 niveaux du
    fichier d'exemple sont ramenes a 255. OK pour un affichage, pas pour une mesure. Option :
    dimZ=[] -> pas de normalisation. (pyCBA : DIM_Z = None.)

P6. Ordre debruitage puis detramage : medfilt2 est applique AVANT le detramage, donc il melange
    les deux trames. Inverser serait plus logique (non change dans pyCBA, a trancher).

P7. Chemins : [DirName '\' FileName{kk}] ne marche que sous Windows ; utiliser fullfile.

--- MAIN_SpiriconRAW_to_ASCII.m -------------------------------------------------------------

R1. [verifie] 'bit16=>double' est BIEN signe : le fichier d'exemple contient des valeurs negatives
    (min -235, fond soustrait) et la lecture non signee donne 65535. Garder 'bit16' (ou 'int16').
    L'orientation (transposition) est correcte : le pic (ligne 89, colonne 92) correspond a
    PeakLocx=92 / PeakLocy=89 de l'en-tete.

R2. [QUESTION OUVERTE] En-tete : Peak=1825,5 ; Valley=-117,5. Les valeurs brutes sont 3651 et -235,
    donc en-tete = brut/2, alors que le script divise par pyrocolorzoom=4 (pic 912,75).
    Le "Color Zoom" est un reglage du logiciel Pyrocam (il n'est pas dans l'en-tete) : s'il vaut 4
    pour ce fichier, l'en-tete est a un autre facteur ; s'il vaut 2, la valeur 4 est fausse.
    A verifier avec une mesure de reference.

R3. Chemins : [PathName '\' FileName{kk}] -> fullfile(PathName,FileName{kk}).

R4. Format de sortie : '-single' = 7 chiffres significatifs, sans importance ici (compteurs
    entiers/4). Le pxscale (myimresize) agrandit les pixels : inutile pour pyCBA, qui doit relire
    l'image native (124x124) avec la taille de pixel de la camera.

R5. colorbar('YTick',[0:(2^camBPP)/8:(2^camBPP) (2^camBPP)]) : la derniere graduation est
    dupliquee (avertissement MATLAB) -> retirer le dernier "(2^camBPP)".

--- MAIN_Import_screenshot_as_ASCII.m -------------------------------------------------------

S1. [lecture du code - bloqueur] methode 'threshold' : CROSSHAIRCLEAN.crosshairthreshold n'existe
    pas (le champ s'appelle 'threshold') -> erreur. Remplacer par CROSSHAIRCLEAN.threshold.

S2. [lecture du code] Meme methode : xsum/ysum sont compares a ymax*seuil et xmax*seuil alors que
    chaque somme a respectivement xmax et ymax termes. Sans effet sur une image carree (320x320),
    faux sinon :
        hlinesy=find(xsum>xmax*CROSSHAIRCLEAN.threshold)';
        vlinesx=find(ysum>ymax*CROSSHAIRCLEAN.threshold)';

S3. [lecture du code] Resampling (zoom>1) : idximg est un uint8 (rgb2ind) et les differences
    col2-col1 / row2-row1 SATURENT A 0 (arithmetique entiere MATLAB) avant abs(). Convertir :
        col1=double(idximg(:,xi)); col2=double(idximg(:,xi+xoff));   (idem pour les lignes)
    Ne concerne que zoom>1 (pas de resampling avec zoom=1).

S4. [lecture du code] ycoord=zeros(1,xmax) -> zeros(1,ymax) (sans consequence, MATLAB agrandit).

S5. [lecture du code] highRGB : RGBpalette(paldepth,:) -> paldepth n'est pas defini
    (utiliser size(RGBpalette,1)).

S6. [verifie sur zoom=1] La methode 'std' trouve TOUJOURS une croix : avec enable=1 sur une image
    sans croix (cas du fichier d'exemple 320x320), 3 colonnes et 3 lignes sont ecrasees. De plus
    elle est centree sur le plus fort saut de dispersion, c'est-a-dire sur le BORD de la ligne :
    pour une croix de 1 pixel c'est correct (epaisseur 3 recouvre), pour une croix de 3 pixels une
    colonne reste. Si la croix reelle est epaisse, regler thickness=5 ou envoyer une capture.

S7. [QUESTION OUVERTE] Normalisation : a=(idx*16383-127)/127 donne +129 par niveau de palette mais
    avec un biais : l'export TIFF (RAW script) calcule idx=round((z+offset)*Zscale) avec
    offset=0.51*16383/127=65.8, donc l'inverse non biaise est z=idx*129-65.8 (et non idx*129-1) ;
    l'ecart (+64.8 comptes, soit la moitie d'un niveau) est inferieur a la quantification
    (129 comptes). A garder si c'est volontaire ("pyrocam specific").

S8. Messages : size(idxcamimg,1) est affiche comme "largeur" : inverser (largeur=size(,2)).
    Encodage : accents des disp() en ANSI ('export�e').
