8) AutoApertureButton_Callback: the mask comes from createMask(hROI,hImage), i.e. from the image OBJECT hImage, while the
   product is made with rfilt = IMAGES{imageNum}.filt (imageNum = value of hImageNumMenu):
        mask = createMask(hROI,hImage);
        croppedimg = rfilt.*mask;
   If hImage is not the image of imageNum (hImage is a variable shared by all images and only refreshed by plot_image;
   for instance the menu was changed to B, which has another size than A, before the display was refreshed, or a reload
   failed halfway), mask and rfilt have different sizes and ".*" errors ("Matrix dimensions must agree"), or worse, if the
   sizes happen to be equal, the mask is placed with the XData/YData of another image.
   Fix: do not depend on hImage; build the mask from the ROI vertices and the pixel centres of rfilt, which is also the
   convention used everywhere else (pixel i centred at i*pixelsize) and the one used in Python (roi_mask).
   Replace the two lines above (inside the for loop) by:

        mask = roiMaskFromROI(hROI, size(rfilt), FILTERS.pixelsize);
        croppedimg = rfilt.*mask;

   and add this function next to AutoApertureButton_Callback (inside the main function, like the others):

    function mask = roiMaskFromROI(h, imgSize, ps)
        % Mask of the pixels whose centre (i*ps, j*ps) is inside the ROI h (imrect, imellipse, impoly), edges included
        v = getVertices(h);                      % polygon (N x 2); for imellipse, the polygon that approximates it
        [X,Y] = meshgrid((1:imgSize(2))*ps, (1:imgSize(1))*ps);
        mask = inpolygon(X, Y, v(:,1), v(:,2));
    end

   Notes: - getVertices exists for imrect, imellipse and impoly (Image Processing Toolbox), so this works for all 5 ROI types.
          - the same function can replace every other createMask(hROI,hImage) of the program (profiles, energy, area, power...).
